# 界面与状态说明

阶段 1A 草案；本轮没有React页面、交互原型或截图验收。字段以 [contracts.md](contracts.md) 为准，所有断点/布局选择是C建议。

## 页面与信息层次

| 页面/区域 | 内容与操作 | 真实状态/错误行为 |
|---|---|---|
| 首页 | 正在进行的讨论列表，话题、专家数、状态；新建讨论表单；可切换查看全部记录 | 列表为空显示“还没有讨论，创建一个话题开始”；加载显示真实请求状态；失败可重试。观察入口只GET和订阅 |
| 创建表单 | 话题多行输入、专家人数默认4；显示“另有1位主持人”（D01已确认）；“生成阵容”按钮 | 按契约校验；提交期间禁重复；网络重试复用requestId；创建成功后请求lineup，失败后保留已有discussionId与输入 |
| 阵容确认 | 主持人单独标识，专家列表含姓名、职业/Title、立场、颜色；提示AI虚构角色 | generating_lineup显示“正在生成阵容”；成功后出现“确认阵容并开始”；无完整阵容不能点击；本版不增加编辑/换人功能 |
| 演播厅顶部 | 话题、运行状态、连接状态、结束按钮；返回首页不停止运行 | 结束按钮只在running启用；stopping显示“正在结束，正在生成总结”；重复操作不再建任务 |
| 专家小窗 | 每位专家的身份、立场摘要、颜色、真实status、publicFocus；主持人单独标识 | idle=待机，preparing=准备发言，speaking=发言中；publicFocus为空显示“暂无公开关注点”；禁止随机轮播/定时假状态 |
| Transcript | 按seq追加，显示姓名、职业/Title、主持人/专家标识、颜色、正文；可跳转所回应发言 | 只消费utterance.created；举手、评分、心跳、JSON、诊断不得变成聊天条目 |
| 共识/分歧 | 两组条目，证据发言可定位；显示“更新至第v条发言” | 无条目显示“尚未形成可确认的共识/分歧”；保留旧版时注明“正在更新”或失败，不能标成覆盖最新内容 |
| 结束总结 | Summary.ready的自然语言，显示基于第v条发言；保留可查记录 | unavailable显示“讨论已结束，总结生成失败”；failed显示中断原因和“新建讨论”，不伪造总结 |

关注点是供用户阅读的简短主题，例如“关注实施成本”，不是隐藏推理摘要。preparing仅在实际意愿/发言任务处理时设置；speaking仅在校验后公开发言发布阶段设置，之后随任务推进回idle，不能用固定延时延长“表演”。状态可能很短暂，UI不为营造活跃而捏造。

每次发言1–2句，按sentences展示为自然段。传输JSON永不直接渲染；代码样式也不能成为泄露原文的后门。总结区独立于普通发言，但当前同样显示1–2句。进入收尾后总等待上限60秒含排队与重试；长总结解释仍待出题方确认。

## 响应式与独立滚动

页面高度以动态视口为边界；应用容器和Grid/Flex子项正确设置min-height:0/min-width:0及overflow。以下像素断点为C建议，不是题面给定值。

| 场景 | 分区方案 | 滚动规则 |
|---|---|---|
| 超宽屏≥1600px | 顶部固定；左侧专家区约22%，中央Transcript约48%，右侧共识/分歧约30%；正文限制舒适行宽 | 三栏独立纵向滚动；共识/分歧在右栏内分别有可滚动内容区；不得扩展body高度 |
| 普通桌面900–1599px | 顶部固定；左侧专家列表；中间Transcript占主宽；右侧综合较窄，可在共识/分歧间切换 | 专家、Transcript、当前综合各自滚动；不会因一栏长文本推动其他栏或整个页面 |
| 窄屏<900px | 顶部紧凑；“讨论/专家/共识/分歧”区域标签切换，一次显示一个主要内容区；结束总结为讨论内独立入口 | 可见区独立滚动，各标签保留自身scrollTop；隐藏区不抢滚动，body不纵向滚动；不强塞三栏制造水平滚动 |
| 首页/阵容页 | 顶部标题固定，表单和列表在剩余视口内；窄屏上下排列且表单不挤出提交操作 | 列表/阵容容器滚动；短视口可让中央内容区滚动，页面壳保持不滚动 |

Transcript默认只在用户已接近底部时跟随新发言；用户向上阅读时保留位置并显示“有新发言，回到底部”。证据链接定位并聚焦目标发言，不重置整页。专家状态变化不抢焦点，不改变用户阅读位置。

软键盘/窗口缩放/长中文标题测试纳入T15；表单控件可聚焦且不被底部操作条遮挡。颜色仅辅助区分，身份同时有文字；正文对比度、字号和行距优先于装饰。尊重减少动态效果偏好，图标必须有可读标签。

## 状态一致性

- created：尚未生成，可发起生成；generating_lineup：显示真实加载；awaiting_confirmation：等待用户确认。
- running：观察者都看到同一份已确认角色与事件顺序；打开第二个页面不会增加开场或模型调用。
- stopping：停止按钮禁用，不再出现新专家发言；迟到的旧任务不能改变界面。
- completed：展示总结或明确不可用状态；failed：展示真实中断，保留历史。
- SSE断线：横幅“连接中断，正在重连”，已有文本不消失；开始按钮等待新快照；结束请求可保留以便停止后台工作，HTTP结果仍按快照确认。
- 控制事件stream.reset：后台重取快照，必要时短暂显示“正在同步记录”；不显示内部游标/原始数据。
- 错误：公开中文message与可执行动作，不能仅显示“失败”或空白，也不能泄露内部调用栈。
