# 阶段5B Fake讨论执行器实施计划

> 执行方式：使用 executing-plans 在当前会话逐任务执行；用户明确禁止子代理/worktree，覆盖Skill默认选项。每项遵循 RED→GREEN→REFACTOR，独立验证后提交。

**Goal:** 已确认阵容经Fake内容驱动执行、增量提炼、有限收尾，正式SQLite与HTTP可读取终态。
**Architecture:** 独立DiscussionProvider与单场runner；SqliteDiscussionStore负责短事务/CAS/预算及事件；调用Limiter由阵容和讨论共同注入。保持001/002不可变，003显式迁移，前端只做严格消费兼容。
**Tech Stack:** 现有Node/TypeScript/Express/node:sqlite/Vitest/React/Playwright；不增加依赖。

## 全局约束
- 只操作当前分支；不读密钥、不加载真实讨论Provider、不触碰stage-4d-live。
- 2场运行含收尾；单场/全局请求2/4；每请求30秒、任务60秒、运行10分钟、收尾60秒。
- 每任务最多2尝试；12成功专家发言；最多2额外主持；独立总结域。
- B(N)=2*[2+12*(N+2)+2*(N+1)]=28N+56，N=1..8为84/112/140/168/196/224/252/280，包含总结预留2次。失败替补也扣同一有限总额，不保证跑满12轮。
- 本轮用户确认覆盖5A阶段划分：允许最小前端运行快照兼容，不增加控制按钮或演播厅。
- 真实SQLite临时fixture、明确Fake、可控计时器；SSE全部留5C。
